# 混合团队实时展示通道

注册中心的团队协调权威与可靠控制事件保持不变。高频聊天展示事件通过独立的持续 TLS 双向连接实时转发，不进入逐事件落盘、同步 HTTP 请求的路径。

## 身份与连接

- 页面请求路由使用环境 `instanceId`，远程环境通常为 `remote-…`。
- Starweave 授权身份使用远程 `sourceInstanceId` 或本地真实 `instanceId`，生成 `starweave-真实实例ID`。真实身份尚未加载时不生成授权 ID。
- 实时连接使用现有注册隧道端口、证书固定校验、令牌与租约认证，不新增公开端口。它与控制连接、ConfigUI 的 TCP 数据流分别使用独立连接。
- 中心依据当前租约确定发送实例，再校验队伍参与者、成员归属与事件类型。远程投影只接受所属队伍和成员，不能通过实时通道注入创建、删除或 TalkTo 路由请求。

## 投递与顺序

文本更新、文本增量、工具展示等事件立即进入内存队列。每条连接采用最多 64 条未确认消息的流水线窗口，异步确认不会让发送方逐条等待网络往返。接收确认发生在事件已进入下一跳的有界队列或已发布到本地页面之后。

单个方向最多保留 2048 条事件、32 MiB 编码内容；单帧上限为 4 MiB。队列满、消息过大或已关闭时明确拒绝接收并记录日志，不使用无界缓存。未确认事件在连接重建后按顺序重放，连接序号和页面事件 ID 分别消除传输与显示重复。

会话切换先经同一实时通道展示，再由可靠控制路径更新中心记录；过期的会话切换版本不会回滚新会话。消息完成和错误也同时保留可靠投递，避免断线或满队列吞掉结束信号。

### MolaChat 混合队伍投影

MolaChat 的增量流接口按成员和会话合并文字，无法自行按 Starweave 消息 ID 恢复乱序。因此源实例为每轮输出附加流 ID、文本位置，并在完成或错误事件中携带该轮完整文本检查点。原有 MolaChat 事件协议保持不变，这些字段由 cmd-proxy 消费。

发起实例将实时和持久化补偿投递合并到同一组有界串行执行器，同一成员始终使用同一个执行器。四个执行器允许不同成员并行；落到同一个执行器的成员共享顺序队列。MolaChat 不消费的 `MESSAGE_UPDATED` 全量版本快照不再进入 RPC 回调队列，增量文字仍立即发送。

结束检查点即使抢先到达，也必须先补齐尚未发送的文本，再关闭一次流。已关闭的流拒绝迟到文本和重复结束事件；投递进度持久化，补发文本使用稳定事件 ID，使回调确认丢失后的重试能复用 MolaChat 的去重机制。实时片段投递失败或缺失时，由持久化结束检查点恢复内容。源实例和发起实例都必须更新到支持检查点的版本；旧事件仍兼容原接口，但不能获得检查点恢复保证。

协调器合并和返回成员信息时以 `state` 为准同步 `status`，避免已有队伍中的 `STARTING` 状态残留导致 MolaChat 将就绪成员显示为离线。

## 恢复与生命周期

短暂连接中断后自动重连并重放未确认事件。同一中心的租约更新不主动丢弃源端待发送队列。进程重启会丢失已经确认的内存展示事件，源实例的会话历史仍是完整内容的权威来源；页面 SSE 重连加载历史，消息完成后也按消息 ID、版本合并历史，补齐丢失的中间展示版本并保留较新的实时内容。

团队创建、删除、状态收敛与 TalkTo 投递仍使用持久化协调链路。两种通道必须在中心和参与实例同步更新后使用。关闭注册服务会释放实时连接、工作线程和内存队列。

旧 MolaChat RPC 注册是可选接入。cmd-proxy 使用独立连接在后台尝试注册，同一地址离线时限制重试频率，失败仅记录 DEBUG 日志；MolaChat 恢复后自动重新注册当前 Provider，仍支持反向调用。此逻辑通过 cmd-proxy 内的注册拦截器实现，不修改 my-rpc，也不改变普通业务 RPC 的异常处理。纯 Starweave 集群无需启动 MolaChat。

`acpSyncRobots` 启动回调和周期心跳复用该可选连接。离线、断线、超时或未收到成功确认时，本轮只记录一条 INFO，不输出堆栈，也不进入普通 RPC 的连续连接重试。连接恢复后继续发送最新的完整快照；回调等待最多 3 秒，最多同时等待 16 个确认，关闭连接会唤醒等待中的调用。

## 验证

测试覆盖远程身份显示、双向高频发送、大帧、断线重放、重复消除、有界接收、成员身份校验和过期会话切换。真实两 JVM 的注册中心与 Netty 隧道测试还检查 200 个连续文本分片的顺序、延迟和文本事件绕过持久化队列，并验证团队恢复、会话切换和删除。
